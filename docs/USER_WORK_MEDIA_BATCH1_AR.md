# الدفعة الأولى — حماية عمل المستخدم ومنظومة صور الإعلان

## المصدر وحدود الاعتماد

عند بدء الدفعة في21 أكتوبر2026 فُحصت فروع GitHub وصفحتا قائمة الفروع وطلبات الدمج والاختبارات. المصدر الأحدث الصحيح هو `d84970332ee451bb176dbeff618ea346620c5e89`، شجرته `eb3dc2d7dc1d6f61bb89b77d694ca4ad6f37d655`؛ CI108 وFocused24 ناجحان وتسليم بايتاته الأصلية موثق. تطابقت الشجرة المحلية المستخرجة مع شجرة GitHub بالكامل. فرع `main` قديم منذ5 سبتمبر، وفرع التجربة `work/broker-experience-v1` عند `22a142666ad92b419eba7e41ea358b7e68199c82`. المصدر المختار يتقدم عليه19 التزامًا ولا يتعارض معه. طلبات92–95 مفتوحة وغير مدمجة؛ هذه الدفعة تتفرع من أحدث المصدر وتستهدف فرعه للمراجعة، ولا تعتمد تلك الطلبات أو تنشرها تلقائيًا.

## الموجود قبل التعديل

المحرر الحالي واحد ويدعم موقعًا مؤكدًا ومسودات حساب خاصة ذات UUID ومراجعة متزايدة، ونسخة استعادة محلية في مجلد التطبيق الخاص، وترتيب الصور الجديدة ومفاتيح رفع مستقلة. الخادم يحمي المسودات حسب المستخدم ويمنع إعادة إدراج الصورة بالمفتاح نفسه بعد نجاحها. المهلات وبعض حالات الانتظار موجودة. الصور تُرفع كاملة عبر Laravel إلى التخزين الحالي؛ لا توجد جلسات TUS أو رفع من آخر بايت. الميكروفون يطلب إذنه عند البدء، ومنتقي Android يستخدم ACTION_OPEN_DOCUMENT دون إذن وصول شامل للصور.

النواقص المرصودة: غياب حارس الخروج؛ ربط مفاتيح الصور بمسارات مؤقتة تتغير عند الاستعادة؛ فشل ملف يوقف طابور الملفات التالية؛ غياب حالة ملف مستقلة؛ رسالة حفظ قد تتأخر عن آخر تعديل؛ حذف ملفات مؤقتة حتى عند فشل الاستعادة؛ إدارة صور الإعلان المحفوظ تعتمد استبدال الكل؛ إعادة حفظ غامضة عند ضياع الاستجابة؛ إعادة التحقق من إنشاء الإعلان مطلوبة داخل قفل الحساب؛ بعض مسارات العرض تعيد الأصل ببياناته؛ GD في Docker يدعم PNG فقط؛ وطلب موقع Home عند البدء يخالف طلب الصلاحية عند الاستخدام في هذه الدفعة.

## التنفيذ المقدم للمراجعة

- توسيع المنظومة الحالية فقط: payload JSON ومفاتيح الصور ومراجعات مسودة الحساب والملفات المحلية. لا جدول أو bucket أو خدمة أو حزمة Flutter جديدة.
- `checkpoint_key` اختياري داخل payload الحالي لإعادة نفس الحفظ دون تكرار أو كتابة جسم مختلف بالمفتاح نفسه. `media_version=1` يتيح ترتيبًا موحدًا من UUID للصورة الجديدة أو `property-ID` لصورة الإعلان نفسه. الخادم يتحقق من الملكية والجاهزية داخل المعاملة. العملاء السابقون يحتفظون بعقدهم الحالي. بعد ترقية الصور إلى الإعلان يكتب الخادم وحده `promoted_image_keys` داخل JSON الحالي مع مراجع `property-ID`، حتى تستعيد إعادة المحاولة نتيجة الإنشاء دون إعادة رفع الصور الناجحة. لا يقبل الخادم هذا الحقل من العميل.
- إعادة المحاولة تخص الملف المتعثر كاملًا، ولا تُعرض كاستكمال من آخر بايت. الحالة والربط والترتيب محفوظة محليًا؛ الملفات الناجحة لا تعاد. ملف بمفتاح ثابت ومحتوى مختلف يُرفض، والاستبدال يستخدم مفتاحًا جديدًا.
- تحفظ الأصول الجديدة في التخزين الخاص. تنتج نسخ JPEG ثابتة للبطاقة640 والتفاصيل1280 والمعرض1920 والتكبير3072 بحد أقصى للضلع، من الأصل مرة واحدة لكل مشتق، دون تكبير الصور الصغيرة. تدوّر الصورة وفق EXIF قبل إعادة الترميز، وتحذف EXIF/GPS/معلومات الجهاز من النسخ العامة. لا يستخرج موقع الإعلان من الصورة.
- امتداد GD الموجود يحتاج دعم libjpeg/libwebp، ومعه امتداد EXIF المضمّن في PHP؛ التعديل محصور في Docker وفحص CI، بلا Composer أو Flutter dependencies. هذه ضرورة موثقة لصيغ JPG/PNG/WebP وتبقى جزءًا من PR الذي يحتاج مراجعة قبل الدمج/النشر.
- HEIC/HEIF/AVIF وHDR/ملفات الألوان الواسعة ليست مدعومة على نحو يمكن ضمانه في الخادم الحالي. لا تسمى تلك الملفات JPG زورًا، ويُعرض رفض واضح مع الصيغ المتاحة. تحسين دعمها الأصلي مستقبلًا يحتاج تقييم decoder وتكلفة الذاكرة وموافقة الاعتماديات؛ لا يُشترى مزود صور. المعالجة الحالية مناسبة لصور RGB الشائعة، ولا تدعي مطابقة لونية دقيقة لملفات ICC/HDR المتخصصة.
- تظل الأصول الخارجية التاريخية `cdn_url` على عقدها القديم؛ لا ينزّل الخادم URL عشوائيًا ولا ينفذ ترحيلًا جماعيًا غير معتمد. الصور الداخلية القديمة تعاد معالجتها عند طلب العرض عبر API. حذف أصل لا يحدث ما دام مرتبطًا بإعلان أو مسودة أخرى.

## حدود التسليم

لا تعديل في السعي أو السجلات المالية أو صلاحيات الحساب أو قائمة الإنشاء أو آليات الذكاء. تعديل الخريطة يقتصر على إذن الموقع وبدائله. لا تغيير قاعدة بيانات أو خدمة مدفوعة أو Production. نتائج CI والبناء توثق في طلب الدمج قبل اعتماد العمل، والقبول على الهاتف يبقى بوابة مستقلة. لا دمج أو نشر دون موافقة صاحب المشروع.

## الملفات والواجهات المتأثرة

- Flutter: `listing_editor_screen.dart` و`listing_recovery_store.dart` و`listing_account_draft_repository.dart`، ومكوّن `listing_draft_photo.dart` ونموذج/معرض تفاصيل الإعلان.
- الصلاحيات: `discovery_location.dart` و`property_location_picker_screen.dart` و`voice_capture_controller.dart` وموضع إجراء الإعدادات في المحرر/قائمة إعداد الإعلان، مع `app_permission_settings.dart` كغلاف لوظائف geolocator الموجودة.
- Android: `MainActivity.kt` لحفظ امتداد MIME الصحيح، و`InAppSpeechInput.kt` للرفض الدائم؛ لا إذن صور شامل أو مكتبة جديدة.
- Laravel: `ListingEditorDraftController` و`ListingEditorDraftService` و`PropertyController`، وخدمة الصور `ListingImageService` وإعداداتها وامتداد `CloudAssetStorageService` الحالي.
- عقود JSON المضافة اختيارية ومتوافقة مع العميل القديم؛ مصدرها المسودة القائمة. لا ترحيل قاعدة بيانات أو تعديل في Composer/Flutter lock. إعداد Docker يضيف دعم JPEG/WebP وEXIF إلى GD الموجود، وهو معروض للمراجعة داخل PR قبل أي اعتماد أو نشر.
- بوابات الاختبار: ملف قبول مستقل جديد، وتوسعة CI الأصلي مع بقاء فحوصه وتوقيع/تشفير APK. الاختبارات التاريخية التي افترضت الأصل العام أو إذن الموقع عند التشغيل استبدلت بتوقعات الخصوصية والطلب الصريح مع إبقاء ملكية الحساب وHTTPS والتحقق المالي.

## ما يحتاج هاتفًا حقيقيًا

إيقاف الشبكة أثناء حفظ ورفع عدة صور ثم العودة، قتل التطبيق وإعادة فتحه، رفض أذونات الميكروفون والموقع ثم تفعيلها من الإعدادات، اختيار الصور عبر مزودي ملفات Android، تحريك الصور والمكبّر مع خط عربي كبير، ملفات هاتف فعلية بزاوية EXIF وRGB وألوان واسعة، وسلوك الذاكرة على هاتف محدود الموارد. الاختبارات الاصطناعية لا تثبت هذه النتائج ولا وصول مزودي البريد/الصوت أو جاهزية خدمة UAT الفعلية.

## ما بقي خارج الدفعة والتكلفة

لا دعم رفع TUS من آخر بايت، ولا تحويل HEIC/AVIF/HDR مضمون أو إدارة ألوان احترافية، ولا ترحيل للأصول الخارجية التاريخية أو معالجة جماعية لمخزن قائم؛ تحتاج تقييمًا منفصلًا بدل فتح مصادر خاصة أو تغيير مزود التخزين. لا خدمات مدفوعة جديدة مطلوبة للدفعة: Laravel/GD والتخزين الحالي ينتجان النسخ؛ إعادة المحاولة الحالية مجانية ضمن البنية القائمة. دعم الصيغ الإضافية مستقبلًا يمكن تقييمه بdecoder مفتوح المصدر محلي قبل التفكير في مزود مدفوع، ويظل تغيير الاعتماديات بحاجة إلى مراجعة وموافقة. لا تغير هذه الدفعة الحصص أو أسعار الخدمات القائمة.
