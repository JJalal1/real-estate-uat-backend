# النسخ والاستعادة قبل #11 والفيديو — 27 أكتوبر 2026

لا توجد في هذه الدفعة نسخة مشفرة كاملة لقاعدة UAT أو استعادة حية مستقلة. قراءة جداول المنصة وفهارسها ليست backup. لم تنفذ هجرة أو ترقية أو رفع صلاحيات. تمرين `scripts/backup_restore_drill.py` منفصل تمامًا عن UAT: لا يقبل DSN، ويشغل حاويتين مؤقتتين بلا شبكة أو ports، ويستعيد dump وأدوارًا وقيودًا وRLS وPostGIS وsequence وبايتات وسائط فعلية بعد تشفير age. يفحص العبث بالأرشيف ويرفض الأدوار العامة ثم يحذف الحاويات والمفاتيح المؤقتة. نتيجته تُرفق من CI عند اكتماله؛ لا تُعد بوابة UAT مجتازة بسبب نجاحه.

## الإجراء المجاني الممكن للنسخة الحقيقية

لا يشترط `pg_dump` أو Supabase CLI شراء Pro. استخدم جهازًا موثوقًا بقرص مشفر وPostgreSQL client مناسب لنسخة الخادم، واتصال TLS عبر session pooler المتاح لـIPv4، وPGSERVICEFILE بصلاحية600 من مدير أسرار؛ لا تضع DSN أو كلمة مرور في command line أو shell history. ممنوع `set -x` وطباعـة البيئة. مثال تصدير للقراءة فقط، بعد توفير الاعتماد والتحقق من قاعدة المصدر:

```sh
umask 077
export PGSERVICEFILE=/secure/aqer/pg_service.conf
pg_dump --dbname=service=aqer_uat --format=custom --file=database.dump
pg_dumpall --dbname=service=aqer_uat --roles-only --no-role-passwords > roles.sql
```

لا تنفذ المثال إذا كان الملف أو الاعتماد غير متاح أو إذا لم يراجع موقع الحفظ. سجّل client/server version، وقت البداية والنهاية، schema/table/row counts، الهجرات، القيود والفهارس والتوابع/triggers/extensions/owners/grants/RLS/sequences. فشل صلاحية تصدير أي schema أو بيانات لازمة للاستعادة مانع صريح؛ لا تُخفه بإضافة exclude أو تعتبر تصدير public فقط نسخة كاملة. ملفات كلمات مرور الأدوار وإعدادات Auth/Vault ومفاتيح تشفير التطبيق/Storage/تكاملات المنصة تُراجع منفصلة وتُحفظ في مدير أسرار؛ dump لا يعيد موارد المزود تلقائيًا. قارن بدليل Supabase الرسمي للأدوار والمخطط والبيانات والجداول المُدارة قبل اختيار هدف الاستعادة.

## Storage واتساق النسخة

PostgreSQL يحفظ metadata للكائنات، ولا يحفظ بايتاتها. أنشئ inventory كاملًا للـbucket الخاص `real-estate-uat` دون نشر أسماء ملفات شخصية، وانسخ كل بايت إلى وجهة مشفرة مستقلة بترويسات خدمة خادمية من مدير أسرار. احسب الحجم وSHA256 لكل كائن داخل manifest مشفر، واحفظ bucket settings والمجلدات والملكية وpolicies. لا تكتف بـsigned URL قد ينتهي، ولا تُحول bucket إلى عام.

يلزم اتفاق نافذة اتساق: إيقاف الكتابات/حذف الملفات مؤقتًا بعد موافقة المالك، أو آلية versioning/immutable snapshot موثقة تثبت أن كل مرجع DB له كائن مطابق وأن deletions أثناء النقل لا تُفقد الاستعادة. مجرد تعداد الكائنات في وقت ثم تنزيلها لاحقًا لا يثبت اتساق DB/Storage. القاعدة الحالية لا تُغيّر لإكمال هذه الدفعة. شفّر DB+manifest+media بتشفير مصادق عليه مثل age لمفتاح استعادة يملكه المالك، واحفظ المفتاح في موضع منفصل. دوّن بصمة الأرشيف المشفر ومكانه الآمن فقط في Git.

## الاستعادة المستقلة والقبول

1. هدف جديد منفصل لا يحمل DSN UAT ولا بيانات أشخاص إضافية، مع موارد مجانية محلية حيث تكفي السعة. لا تستعد فوق المصدر.
2. فك التشفير في مساحة محمية، تحقق من SHA ورفض archive traversal، ثم راجع mapping الأدوار المدارة والامتدادات وAuth/Vault. لا تطبق roles.sql عميانيًا على Supabase قائم.
3. استعد schema/data/sequences/constraints/indexes/owners/grants/RLS، ثم بايتات Storage وخصائص bucket الخاصة. استعادة محلية لا تثبت وحدها تكافؤ كل خدمة Supabase المُدارة؛ سجّل الاستثناءات واختبرها في الهدف المناسب قبل اجتياز البوابة.
4. قارن manifest كاملًا: أعداد وبصمات البيانات، 59 هجرة قبل أي تغيير مؤجل، FK/UNIQUE/CHECK، صلاحيات PUBLIC/anon/authenticated، RLS، جميع المراجع إلى الملفات، SHA لكل أصل ومشتق، رفض قراءة حساب آخر، وحذف ملفات اختبار اصطناعية دون مساس بالأصل.
5. شغّل Laravel read-only smoke ثم رحلات اصطناعية في الهدف المستقل مع push/video/OTP للخارج OFF. قِس RTO/RPO الفعليين؛ هدفهما يحتاج قرار المالك، ولا تُخترع مدد احتفاظ.
6. إيصال مؤرخ يراجعه المالك: المصدر والهدف، اكتمال التغطية، مكان الأرشيف والمفتاح المنفصل، نتائج التحقق، الاستثناءات، خطة rollback وخطوات التفعيل المقترحة. بعده فقط موافقة الخطوة ذات الأثر والهجرة المحددة.

## تفعيل #11

PR #115 هو الفرع الوحيد. بعد النسخة والاستعادة والقبول: snapshot جديد للهجرات والملكية؛ تطبيق migration intents وحدها؛ فحص RLS وREVOKE وقيودها وفهارسها؛ ضبط حدود حجم/MIME للـbucket ضمن خطة؛ canary لحساب اصطناعي واحد؛ HEAD/PATCH6MiB وانقطاع وتجديد و409/410 وoffset غير صحيح وملف تغير وfinalize ملتبس وحساب ثانٍ؛ اختبار تنظيف tombstones بعد انتهاء كل صلاحية TUS؛ ثم Android مع قتل التطبيق وتبديل الشبكة. لا تقلب Flutter build flag وLaravel flag عامًا من نجاح canary واحد.

Rollback: أغلق العلمين أولًا؛ أبقِ intent rows ومهمة التطهير حتى انتهاء كل signed upload/session؛ لا تنفذ down أو تحذف أصلًا مستخدمًا. استعادة DB وحدها إلى زمن سابق قد تفقد مرجع الملف، لذلك rollback البيانات لا ينفذ إلا على manifest/Storage متسقين وخطة مجازة.
