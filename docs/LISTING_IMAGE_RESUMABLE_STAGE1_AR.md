# عقار | البند #11 — الاستئناف الحقيقي لرفع الصور (مرحلة هندسية معزولة)

> **غير جاهز للدمج أو UAT أو الاستخدام**. هذه مرحلة تأسيس لم تُربط بواجهات Flutter أو مسارات Laravel، وليس إعلان اكتمال. لا تفعّل العلم `LISTING_IMAGE_RESUMABLE_ENABLED` ولا تعتمدها في الإنتاج.

## الواقع المتحقق منه
- رفع الصور الحالي: multipart من Flutter إلى Laravel، يعيد المحاولة على مستوى **الملف كاملًا** باستخدام UUID ثابت، مراجعة revision لكل مسودة، واسترجاع الملفات محليًا؛ الاختبارات السابقة تغطي عدم التكرار وفقدان الرد وتبديل الحساب.
- معيار #11 الحقيقي، إذا قصد استكمال البايتات، غير محقق بعد؛ لأن Dio يعيد إرسال الملف كاملًا.
- Supabase Storage يوثق بروتوكول TUS للرفع القابل للاستئناف بحزم **6 MiB**. المصدر: https://supabase.com/docs/guides/storage/uploads/resumable-uploads
- المسار العام UAT والـProduction غير معدل؛ PR الفيديو #111 متوقف كما أمر المالك.

## الكود الموجود في هذا الفرع فقط
- `config/listing_media.php`: علم `resumable_uploads_enabled` مطفأ افتراضيًا.
- `CloudAssetStorageService::createPrivateResumableTicket`: تأسيس إصدار token محدود المسار عبر Supabase، دون كشف المفتاح الخدمي.
- `ListingImageService::finalizeResumablePrivate`: يتحقق من حجم الملف وبصمة SHA-256 ونوعه، ويصنع نسخ JPEG المنزوعة البيانات؛ **غير موصول بنقطة إنهاء API ولا يضيف الصورة للمسودة**.
- اختبار وحدة وتصريح: `PrivateResumableImageTicketTest`. نجاح CI لا يغني عن اختبار موثق للـTUS signed authorization الحقيقي؛ توثيق Supabase العام يعرض TUS للمستخدم المصادق عبر Supabase Auth، بينما تطبيق عقار يستخدم API token مستقل. يلزم تأكيد توافق تواقيع الرفع مع TUS قبل بدء ربط الجهاز.

## المطلوب قبل اعتبار هذه الميزة مكتملة
1. تحقق تعاقد `signed upload token` مع TUS `x-signature` في الإصدار الحي لـSupabase **عبر ملف اصطناعي فقط**، مع صلاحيات مسار خاص وبدون كشف server key. لا تعطل RLS أو تفتح bucket.
2. تصميم حالة نوايا uploads على قاعدة UAT بعد **نسخة احتياطية قابلة للاستعادة**: owner+draft+UUID+SHA256+size+mime+expiry+single-use; منع إعادة استخدام token بعد الحذف أو تبديل الحساب.
3. نقطة إنشاء تذكرة مصادق عليها ومعدودة الحصة `max 12` و`max 8 MiB`، ثم إنهاء ذري يفحص التملك/revision وحالة المسودة الحالية والبصمة والحجم والنوع والدقة قبل اعتماد الصورة.
4. جامع مخلفات للـunsigned/uncommitted uploads بعد المهلة، حذف/إبطال التذكرة عند إزالة الصورة أو حذف المسودة أو إقفال الحساب؛ لا تتراكم objects. راعِ احتمال upload ينجح بينما الرد ينقطع.
5. عميل Flutter TUS موثوق يدعم حفظ fingerprint/offset بصورة آمنة مع account scoping، واسترداد upload HEAD/PATCH، وعدم إعادة إرسال الجزء المكتمل، ومعالجة 401/403/409/413/423 وtimeout، وإلغاء آمن.
6. اختبارات تكامل ضد storage الحقيقي وLaravel وFlutter مع قطع اتصال بعد 6 MiB، وصول متكرر، حسابين، نقل مخطط أثناء الرفع، انتهاء تصريح، وبصمة خاطئة. ثم مراجعة الأداء والحدود ونشر UAT فقط مع flag OFF، ثم canary وتشغيل محدود.
7. مطابقة مواصفة الـ32 الأصلية للبند #11 وإثبات قيمة الاستئناف الفعلي؛ تسجيل SHA والاختبارات ونسخة Android الموحدة في المصفوفة.

**توقف دمج هذا الفرع حتى اكتمال موانع الأمان السابقة.** لا تدع نجاح اختبار الـticket المحدود يوحي بأن رفع الصورة مستأنف فعلًا. الهدف النهائي لا يزال النسخة الحالية المكتملة البنود الـ32، والفيديو مؤجل مؤقتًا فقط قبل النشر.

## تحديث تنفيذ 23 أكتوبر 2026 — متابعة PR #115

- أُضيفت **هجرة Laravel غير مطبقة** `2026_10_23_220000_create_listing_image_upload_intents.php` ونموذج `ListingImageUploadIntent`، يخزنان المالك والمسودة والصورة وSHA256 والحجم والنوع والتوقيع والمهلة، مع RLS وREVOKE للأدوار `anon/authenticated`.
- أضيف `ListingImageUploadIntentService` لحجز معرّف الصورة والتحقق من العضوية والملكية وتطابق revision والحجم، وإصدار تذكرة مقيدة بالمسار والتوقيع، وإكمال ذري يسجل الصورة فقط بعد تحقق bytes وMIME وSHA256 والمشتقات. نقطة API الإصدار والإكمال موجودتان خلف علم **OFF** وقيود throttle.
- **CI المخصص** على `dbb6f9d3d44dfb53e8f75ade5d197df54b3dfd13`: **11 tests / 153 assertions PASS**، وتشمل حظر endpoint افتراضيًا، رفض حساب آخر، حدود الحجم ومحتوى غير صالح، والتحقق من المشتقات. لا يعني هذا اجتياز بروتوكول TUS مع Supabase الحي.
- **لم يتم نشر أو دمج** هذا الفرع في UAT؛ لا تطبيق للهجرة على قاعدة Supabase. آخر نشر UAT الناجح يخص #1.
- وثائق Supabase الرسمية تؤكد `x-signature` للتذاكر و6MiB chunks، وأن تذكرة الرفع الموقعة صالحة ساعتين، وقد تبقى جلسة TUS لمدة 24 ساعة. أبقِ `purge_after` بعد 26 ساعة للتنظيف، ولا يُعتمد كمنظف منفذ حتى إضافة purge آمن ومستمر.

### نواقص مانعة للتفعيل (لم تنجز بعد)
1. ربط Flutter عميل TUS موثوق يدعم حفظ offset واسترداد PATCH بعد انقطاع الاتصال؛ لم تعدل نسخة الهاتف هنا.
2. تصميم تنظيف آمن للمخلفات وللتذاكر بعد حذف الصورة/المسودة ومرور `purge_after`، مع ضمان عدم حذف صورة مكتملة وتفادي سباق النقل المتأخر.
3. اختبار تكامل حقيقي بتذكرة موقعة وTUS HEAD/PATCH على Supabase UAT، وملف اصطناعي أكبر من 6MiB، مع فحص عدم كشف الأسرار أو تسرب بيانات.
4. نسخة احتياطية لقاعدة UAT **مختبرة الاستعادة** قبل تطبيق الهجرة؛ لا تعوّض نجاح CI تلك الخطوة.
5. حالات الطلب المكرر والغلق وإزالة الصورة وتبديل الحساب وانتهاء التوقيع والاختبار على Flutter وUAT وهاتف فعلي، مع مراقبة الموارد.
6. لا تدمج PR #115 قبل إثبات جميع النقاط السابقة؛ علم الميزة OFF ليس تصريحًا بنشر تصميم غير مكتمل. تابع بقية البنود في الوقت نفسه دون المساس بالفيديو أو Production.


## متابعة هندسية أخيرة — تنظيف المخلفات والرجوع الآمن
- أضيفت آلية حفظ tombstones في migration عند حذف الحساب/المسودة باستخدام `nullOnDelete` بدل حذف سجل الرفع وإضاعة أثر الملف غير المكتمل.
- `ListingImageUploadIntentService::purgeExpired()` يبحث فقط عن محاولات `pending/canceled` المنتهية بعد نافذة TUS، ويتأكد من عدم ارتباطها بأي صورة في مسودة أو إعلان قبل الحذف؛ يحتفظ بالسجل إن فشل مزود التخزين لتتم إعادة المحاولة.
- حذف الصورة غير المكتملة وحذف المسودة يضع المحاولات المعلقة في حالة `canceled`. هذا **إلغاء منطقي**؛ تذكرة Supabase المصدرة لا يمكن افتراض إبطالها فورًا. التنظيف مؤجل إلى انتهاء صلاحية جلسة النقل.
- أضيفت مهمة `listing-media:purge-expired-upload-intents` المجدولة، تحمي حالة عدم تطبيق الهجرة، وتواصل التنظيف حتى عند إيقاف علم الميزة بعد الاستخدام.
- **نتيجة CI مثبتة قبل آخر تعديل لجدولة التنظيف:** 13 اختبارًا و163 تأكيدًا ناجحًا على `3b2c18de8eda2321f9c74303e28759b02399dd6e`. لا تعتبر أي SHA أحدث أخضر حتى تظهر نتائج فحوصه الخاصة.
- **موانع لازالت قائمة:** لا عميل Flutter TUS في التطبيق حتى الآن؛ لا تجربة حية مع Supabase؛ لا نسخة احتياطية مجربة لهجرة UAT؛ لا إثبات اختبار الهاتف أو سباق HEAD/PATCH/انتهاء التذاكر؛ لا دمج أو نشر.
