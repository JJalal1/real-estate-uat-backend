## الواقع المتحقق منه
- رفع الصور الحالي: multipart من Flutter إلى Laravel، يعيد المحاولة على مستوى **الملف كاملًا** باستخدام UUID ثابت، مراجعة revision لكل مسودة، واسترجاع الملفات محليًا؛ الاختبارات السابقة تغطي عدم التكرار وفقدان الرد وتبديل الحساب.
- معيار #11 الحقيقي، إذا قصد استكمال البايتات، غير محقق بعد؛ لأن Dio يعيد إرسال الملف كاملًا.
- Supabase Storage يوثق بروتوكول TUS للرفع القابل للاستئناف بحزم **6 MiB**. المصدر: https://supabase.com/docs/guides/storage/uploads/resumable-uploads
- المسار العام UAT والـProduction غير معدل؛ PR الفيديو #111 متوقف كما أمر المالك.

## الكود الموجود في هذا الفرع فقط
- `config/listing_media.php`: علم `resumable_uploads_enabled` مطفأ افتراضيًا.
- `CloudAssetStorageService::createPrivateResumableTicket`: تأسيس إصدار token محدود المسار عبر Supabase، دون كشف المفتاح الخدمي.
- `ListingImageService::finalizeResumablePrivate`: يتحقق من حجم الملف وبصمة SHA-256 ونوعه، ويصنع نسخ JPEG المنزوعة البيانات؛ **غير موصول بنقطة إنهاء API ولا يضيف الصورة للمسودة**.
- اختبار وحدة وتصريح: `PrivateResumableImageTicketTest`. نجاح CI لا يغني عن اختبار موثق للـTUS signed authorization الحقيقي؛ توثيق Supabase العام يعرض TUS للمستخدم المصادق عبر Supabase Auth، بينما تطبيق عقار يستخدم API token مستقل. يلزم تأكيد توافق تواقيع الرفع مع TUS قبل بدء ربط الجهاز.

## المطلوب قبل اعتبار هذه الميزة مكتملة
1. تحقق تعاقد `signed upload token` مع TUS `x-signature` في الإصدار الحي لـSupabase **عبر ملف اصطناعي فقط**، مع صلاحيات مسار خاص وبدون كشف server key. لا تعطل RLS أو تفتح bucket.
2. تصميم حالة نوايا uploads على قاعدة UAT بعد **نسخة احتياطية قابلة للاستعادة**: owner+draft+UUID+SHA256+size+mime+expiry+single-use; منع إعادة استخدام token بعد الحذف أو تبديل الحساب.
3. نقطة إنشاء تذكرة مصادق عليها ومعدودة الحصة `max 12` و`max 8 MiB`، ثم إنهاء ذري يفحص التملك/revision وحالة المسودة الحالية والبصمة والحجم والنوع والدقة قبل اعتماد الصورة.
4. جامع مخلفات للـunsigned/uncommitted uploads بعد المهلة، حذف/إبطال التذكرة عند إزالة الصورة أو حذف المسودة أو إقفال الحساب؛ لا تتراكم objects. راعِ احتمال upload ينجح بينما الرد ينقطع.
5. عميل Flutter TUS موثوق يدعم حفظ fingerprint/offset بصورة آمنة مع account scoping، واسترداد upload HEAD/PATCH، وعدم إعادة إرسال الجزء المكتمل، ومعالجة 401/403/409/413/423 وtimeout، وإلغاء آمن.
6. اختبارات تكامل ضد storage الحقيقي وLaravel وFlutter مع قطع اتصال بعد 6 MiB، وصول متكرر، حسابين، نقل مخطط أثناء الرفع، انتهاء تصريح، وبصمة خاطئة. ثم مراجعة الأداء والحدود ونشر UAT فقط مع flag OFF، ثم canary وتشغيل محدود.
7. مطابقة مواصفة الـ32 الأصلية للبند #11 وإثبات قيمة الاستئناف الفعلي؛ تسجيل SHA والاختبارات ونسخة Android الموحدة في المصفوفة.

**توقف دمج هذا الفرع حتى اكتمال موانع الأمان السابقة.** لا تدع نجاح اختبار الـticket المحدود يوحي بأن رفع الصورة مستأنف فعلًا. الهدف النهائي لا يزال النسخة الحالية المكتملة البنود الـ32، والفيديو مؤجل مؤقتًا فقط قبل النشر.

- `ListingImageUploadIntentService::purgeExpired()` يبحث فقط عن محاولات `pending/canceled` المنتهية بعد نافذة TUS، ويتأكد من عدم ارتباطها بأي صورة في مسودة أو إعلان قبل الحذف؛ يحتفظ بالسجل إن فشل مزود التخزين لتتم إعادة المحاولة.
