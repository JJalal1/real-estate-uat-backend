## جولات Work المطلوبة قبل تسليم APK للاختبار
1. **الجولة A، إغلاق العمل الداخلي:** #16 جرد كامل للشاشات والأدوار وحالات الأخطاء؛ #32 التناسق وRTL وAPI36؛ #2 قياس ترميز صور24MP المتزامن؛ #4 إعداد حالة علامة مائية حقيقية بحسب قرار تفعيلها؛ #5 مسار مشاركة UAT قابل للتجربة مع فصل الدومين الرسمي. كل بند مع اختبارات جديدة عند الحاجة ثم PR وCI وUAT.
2. **الجولة B، الخدمات والقرارات الرسمية:** #8 Queue/FCM الحقيقي ثم مراقبة التسليم؛ #22 التحقق من App Links الرسمي؛ #26 تحديث موقع مع package/store/signing؛ #31 مزود OTP ودورة الحذف وسياسة الاحتفاظ. **افصل أعمال الكود الممكنة عن هوية/صلاحيات/تكلفة لا يملك Work اعتمادها**. لا تتعامل مع fake FCM أو debug signing كإثبات جاهزية إنتاج.
3. **الجولة C، تسليم المالك:** أنشئ APK UAT واحدًا مبنيًا على HEAD موحد بعد جميع الدمجات وCI، سجل رقم build وSHA256 وبيئة API وتوقيع UAT، حسابات اصطناعية ودليل اختبار آمن، وخطوات موجزة لكل من الـ15 بالإضافة إلى الـ9 حين تُفك بواباتها. حدد ما يلزم جهازًا فعليًا أو حكمًا بصريًا أو خدمة خارجية.
4. **الجولة D، دورة الإصلاح/الإغلاق:** كل حالة قبول ناجحة تصبح C بدليل owner acceptance + SHA وتاريخ/البيئة، وكل فشل يعاد إلى Work لإصلاح السبب. لا تفترض أن user tap اختبار أمان الخادم، ولا ترفع حالة كل الـ29 جماعيًا.

## ما لا يستطيع Work إغلاقه وحده دون المالك أو بيئة رسمية
- **جهاز Android حقيقي وحكم الصور البشري**: #1 ومراجعات Native لكل مسارات T/W؛ Work يجهز APK والسيناريوهات لكن لا يدعي أنه لمس الجهاز.
- **هوية المتجر ودومين رسمي وتوقيع Play/مفتاح upload ورابط متجر**: #5/#22/#26؛ يحتاج قرارًا وتكوينًا آمنًا من المالك. لا تخترع package أو شهادة أو domain.
- **Firebase/FCM ومزود OTP والعمال المدفوعون والسياسات**: #8/#31، موافقة وتكوين أسرار رسمي؛ Work يكتب الكود والاختبارات ثم يختبر التكامل عندما تتاح الخدمات.
- **قرارات تشغيل العلامة المائية والميزات الاختيارية**: #4 و#20؛ لا تفعّل أعلامًا وتكاليف دون إذن.
- **موافقة تشغيل موارد/حمل تجاري**: Issue #109، SLO وحمل 30 دقيقة على always-on معتمد وقواعد التنبيه، والنسخ/الاستعادة المستقلة، والـ3 مؤجلة. هذه بوابات إصدار **منفصلة عن فرز الـ29** ولا يصح تجاوزها بمجرد أن كل بند صار T.

## بوابة تحويل W إلى T
أثبت أن كل الشيفرة/التكامل/الخادم/القاعدة/Storage والعقود اللازمة للبند موجودة ومختبرة على SHA محدد، ولا توجد خدمات/هوية/كلفة ناقصة لازمة لاختبار الوظيفة فعليًا، ثم أرفق APK موحدًا وخطوات اختبار المالك وحساباته الاصطناعية. وإلا لا تضع T، بل أبقِ W مع اسم مانع محدد وطلب واحد قابل للتنفيذ.

**تحذير:** تبقى #3/#11/#21 مؤجلة خارج هذه الـ29، ولا تُغلق من هذه الوثيقة. #11 يحتاج نسخة PostgreSQL كاملة مشفرة + استعادة مستقلة قبل DDL، و#3/#21 يلزمان قرار تكلفة وأمان. Release Candidate / Production / المتاجر تحتاج GO/NO-GO منفصلًا وموافقة صريحة، ولو أصبحت كل البنود مكتملة أو في انتظار الهاتف.
