## جرد الموجود وحدود التنفيذ

موجود: مشتقات صور خاصة من الدفعة الأولى، معرض/تكبير، قوائم API بصفحات، PropertyAsset وكشف التكرار المؤكد/المشتبه، بلاغات SupportCase ومراجعة بشرية وطابور مهام موحد، وبلاغ المحادثة ذي وصول خاص مدقق. لا علاقة حظر حساب-حساب حاليًا، ولا مسار طلب حذف حساب مخصص. لا مزود فحص صور دلالي موجود معتمد؛ لا تفترض هذه الدفعة أن أبعاد الصورة أو لونها يثبتان صلتها بالعقار.

يحافظ اسم العرض على package/applicationId/روابط/مفاتيح التخزين والتوقيع وفق نظام البناء القائم. الاسم على الجهاز «عقار»، والاسم المرجعي للمتجر «عقار | Aqer عقارات اليمن». لا إنشاء حساب متجر أو نشر. الدخول إلى حساب موجود يبقى دون اسم؛ الاسم في التسجيل فقط، كما يقتضي تصحيح المالك السابق.

## مبررات المخطط والعقود للمراجعة

علاقة حظر مستقلة ومحدودة لازمة عند غيابها؛ لا يصح تحويل سجل الشكاوى إلى قائمة حظر أو الاعتماد على إخفاء Flutter. إن أضيفت migration فهي موجهة للمراجعة والاختبار في قاعدة مؤقتة فقط، مع RLS وحرمان الوصول المباشر وملكية Laravel. طلب الحذف وفحص الصور البشري يعيدان استخدام SupportCase/ListingReview بدل جداول أو طوابير موازية. لا تعديل حصص/ماليات أو صلاحيات تشغيلية.

## موافقات منفصلة لا تجمد بقية العمل

- الصفحة14: «اعرض Preview أولًا ... بعد اعتماد المالك فقط، صدّر Production Assets». أصول الهوية المقدمة للمراجعة لا تعني موافقة إنتاج أو تفعيل ختم نهائي على وسائط حية.
- الصفحة3/5: لا مشاركة صور خاصة مع مزود جديد أو شراء خدمة فحص؛ البديل الحالي مراجعة بشرية موثقة داخل المسار القائم.
- الصفحة8: حصر علاقات البيانات ومسار طلب غير تدميري؛ مدد الاحتفاظ والحذف النهائي تبقى قرار المالك ومستشاريه. لا حذف فعلي لمستخدم أو سجل أو أصل في البيئة الحية.
- الصفحة10: إعداد فروع وPR ومخرجات مراجعة فقط؛ لا دمج أو نشر UAT/Production أو شراء أو حذف بيانات فعلية.

تضاف أدلة التنفيذ والاختبارات والمقارنة في PR؛ فحص هاتف متوسط وشبكة بطيئة وNative/الأذونات بوابات مستقلة عن الاختبارات الآلية.
