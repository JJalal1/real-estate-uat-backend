# تنظيف وسائط المسودات عند حذف الحساب — 25 أكتوبر 2026

## المشكلة والإصلاح

كانت `AccountErasureService` تحذف صفوف `listing_editor_drafts` دون حذف أصول الصور غير المنشورة ومشتقاتها. يبقى الملف خاصًا لكنه يفقد مرجع التنظيف، فلا تكفي إزالة صف المسودة لإثبات دورة حذف البيانات.

يجمع الإصلاح مسارات صور المسودات تحت قفل الحساب نفسه الذي يستخدمه محرر الإعلان. يتحقق من بادئة ملكية الحساب، ويحذف صفوف المسودات ضمن المعاملة، ثم ينظف الأصل ومشتقات v1/v2 فقط إذا لم يبق مرجع إعلان أو مسودة أخرى. تبقى صور الإعلان المؤرشف المشار إليها ضمن سياسة الاحتفاظ الحالية، ولا تمس ملفات الحساب الآخر. انتقل فحص منع حذف حساب الموظف وقراءة مسارات التحقق والصورة المهنية إلى داخل قفل الحساب لتجنب الاعتماد على نسخة سابقة من الحساب.

التنظيف في هذا المسار صار صارمًا: فشل Storage يلغي معاملة الحذف ويحتفظ بمسارات المسودات والتوكنات لتسهيل إعادة المحاولة، ولا يصدر إيصال نجاح. كالسابق، لا توفر PostgreSQL وStorage معاملة موزعة؛ إذا حذف المزود بعض الملفات قبل فشل لاحق، لا يمكن إعادة البايتات تلقائيًا. تعيد المحاولة حذف المسارات نفسها بصورة idempotent، وتبقى هذه المحدودية موثقة. التنظيف اللاحق لحفظ محرر عادي يبقى best effort كي لا يحول حفظًا مؤكدًا إلى فشل وهمي.

## إثبات الانحدار

- اختبار HTTP فعلي داخل Laravel مع filesystem آمن: حذف المسودة والصور غير المستخدمة والتوكن، والإبقاء على صورة لها مرجع إعلان وملفات ومسودة حساب آخر.
- اختبار مزود HTTP يعيد 503: rollback للحساب والمسودة والإعلان والتوكن، ثم إعادة محاولة ناجحة دون قبول 503.
- رفض مسار مسودة غير متسق مع ملكية الحساب، دون حذف الملف الآخر أو تأكيد حذف الحساب.
- ضُمّت اختبارات الحذف إلى مصفوفة SQLite/PostgreSQL، وأضيف رفع صورة لمسودة غير منشورة ثم إثبات حذف أصلها وجميع مشتقاتها إلى رحلة HTTP السحابية v2. لا يمثل تعديل الاختبار نجاحًا حيًا قبل تشغيله وقراءة نتيجته.

لا هجرة قاعدة بيانات، ولا تغيير grants/RLS أو حدود المعدل أو أدوار الموظفين. يعتمد المسار السحابي على إصلاح بروتوكول DELETE في PR #138.
