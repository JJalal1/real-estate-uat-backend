هذا تدقيق محدد للمصدر والاختبارات والبيئة التي أمكن الوصول إليها، وليس شهادة خلو من الثغرات أو اختبار اختراق شامل. النسخة التشغيلية الرسمية هي `real-estate-uat-api-frankfurt` في My Workspace؛ لا علاقة للخدمات القديمة أو Oregon بهذا الإيصال. نتائج CI النهائية وأصل APK تُقرأ من إيصال التسليم، ولا تُستنتج من وجود هذا المستند.

## ما تغير وما بقي محفوظًا

PR #160 يستكمل هوية UAT وإشعارات SDK الأصلي: لا SDK مكرر، ولا مفتاح خادمي في التطبيق، ولا تفعيل Production. أضيف سياج جلسة وحساب ورمز جهاز للعرض والنقر و callbacks المتأخرة، وإلغاء محلي قبل انتظار الشبكة، وإرسال data-only دون نص خاص، وطابور push مستقل وعامل nonroot و readiness بلا إرسال. تفاصيل التفعيل في [دليل Push](AQER_PUSH_ACTIVATION_2026-10-27_AR.md).

قياس الحمل المعزول كشف زيادة استعلامات الصفحة مع تعدد الملاك: 47 استعلامًا لصفحة 20 إعلانًا في عينة 10k. جُمعت قراءات المستحقات في الخدمة المعتمدة، مع إبقاء predicates المبلغ/الحالة/الاستحقاق، وتفعيل القيد وإشعاره والمبالغ والسجلات كما كانت. أضيف اختبار نمو 1→20 مالكًا واختبار للقيود والإشعار وعدم التكرار وحالة disputed والمبلغ المسدد. لم تتغير نسب السعي أو الاتفاقات أو القيود المالية أو قيمها لإكمال بند آخر.

لم نعد تنفيذ حماية 24MP أو العلامة أو الشاشات أو EXIF أو المسودات السابقة. أُعيدت اختبارات تراجعها على العمل الحالي. ملفات PR111/115 القديمة قورنت وحُلّت تعارضاتها مع الحمايات الحالية بدل نسخها فوقها، وبقيت خارج الفرع الموحد إلى اجتياز بواباتها.

## PostgreSQL و Storage الحيان

الفحص بالقراءة فقط أكد: PostgreSQL17.6، build المزود 17.6.1.166، و PostGIS3.3.7، و 59 هجرة Laravel. يوجد 88 جدولًا عامًا وكلها RLS مفعّل؛ لا CRUD مباشر ممنوح لـ PUBLIC/anon/authenticated؛ صفر فهرس عام غير صالح وصفر قيد غير متحقق عند الفحص. لا bucket عام. جدول intents وجدول الفيديو المؤجلان غير موجودين. كان عدد Storage objects379، و jobs/failed_jobs/push_devices صفرًا؛ هذه لقطة لجداول معطلة الإرسال وليست إثبات عامل سليم.

تحذيرات security كانت 88 INFO بشأن RLS بلا policy؛ في هذا التصميم Laravel هو مرجع التفويض والموبايل لا يقرأ جداول التطبيق مباشرة، لذلك deny-all مقصود. تحذيرات performance تضمنت 152 unused_index INFO؛ لم يُحذف أي فهرس بناء عليها. لا تُفتح GRANT أو RLS لمعالجة خطأ التطبيق. صلاحية مفتاح Storage الخادمي لا تعفي Laravel من فحص المالك والمسودة والدور.

الـ bucket الحالي خاص، لكن file_size_limit و allowed_mime_types غير مضبوطين. ذلك بوابة قبل TUS المباشر، وليس ترخيصًا لتفعيله الآن. قبل #11 تضبط حدود المزود وفق [بوابة Storage المشتركة وحدود8/10MiB](AQER_STORAGE_ADMISSION_GATE_2026-10-27_AR.md)؛ حد الإعلان8MiB يبقى في Laravel، والـbucket المشترك يحتاج الحفاظ على وثائق10MiB وعدم خفضها إلى8MiB. في فرع الفيديو جُهز bucket خاص مستقل مطلوب عبر `SUPABASE_VIDEO_STORAGE_BUCKET` كي لا يؤدي حد الفيديو 50MiB إلى توسيع admission للصور/TUS؛ غيابه أو مطابقته للـ bucket الأساسي يمنعان الشبكة لهذا المسار. يلزم ضبطه على Web والعامل عند التفعيل، ولا يُنشأ bucket أو تتغير سياسة حيّة في هذه الدفعة.

تحديث Supabase الخاص بالجداول الجديدة و Data/GraphQL API يبدأ 30 أكتوبر 2026 وفق changelog الرسمي: منح DataAPI للجداول الجديدة يصبح opt-in. لا يتطلب ذلك فتح جداول Laravel ولا يغير اتصال PostgreSQL المباشر. راجعت كذلك إصدارات PostgreSQL الأمنية الأحدث؛ سلسلة 17.11 تحتوي إصلاحات لاحقة لـ 17.6. لا يثبت رقم النسخة وحده غياب backports لدى Supabase؛ يلزم تأكيد المزود لخريطة الإصلاحات وخطة نسخة/استعادة وصيانة معتمدة. لم تحدث ترقية. تمرين CI الاصطناعي أبلغ 17.5 لصورة PostGIS الحالية؛ لا يوصف بأنه اختبار لنسخة مزود محدثة ولا يستخدم كنسخة إنتاج معتمدة.

المراجع: https://supabase.com/changelog/45329-breaking-change-tables-not-exposed-to-data-and-graphql-api-automatically ؛ https://www.postgresql.org/support/security/ ؛ https://www.postgresql.org/docs/17/release-17-11.html .

## حذف الحساب والسياسة التي تحتاج اعتمادًا

التنفيذ الحالي يقفل المستخدم قبل جمع ملفات المسودات وإبطال البيانات والجلسات. فشل Storage لا يعطي receipt نجاح؛ تبقى metadata عبر rollback لإعادة المحاولة، وحذف الكائن الغائب idempotent. السباقات 5 في AuthRace والتحقق من PostgreSQL جزء من الدليل. لا يُحذف حساب موظف قبل نقل المهام والصلاحيات.

| فئة | السلوك الحالي | قرار لم يُخترع |
|---|---|---|
| الهوية الشخصية والاتصال والصورة المهنية | anonymization للاسم/البريد، إزالة الهاتف والحقول الشخصية والصورة، وإبطال الوصول | مراجعة نص الإفصاح النهائي |
| جلسات/رموز/أجهزة/تفضيلات وبيانات مؤقتة ومسودات | إبطال/حذف بحسب الخدمة، وتنظيف الملفات غير المشتركة مع حماية المراجع | قبول هاتف ومسار الويب/OTP الحقيقي |
| إعلانات منشورة وبيانات مرتبطة | تؤرشف وتزال بيانات الاتصال؛ ملفات منشورات مؤرشفة ومراجع مشتركة تحتاج قرار احتفاظ واضح | تحديد ما يمحى وما يحتفظ به ومَن يصل إليه |
| مالية/اتفاقات/audit/رسائل مشتركة | يحتفظ الكود بسجلات سلامة وتعاملات محددة؛ لا تُمحى دفاتر مالية لإغلاق 31 | الغرض والمدة والأساس والجهة المخولة تحتاج اعتمادًا؛ لا نزعم مسوغًا قانونيًا أو مدة |

صفحة حذف UAT وعقود التحقق لا تحل محل URL رسمي معلن في المتجر ومزود OTP معتمد لليمن وسياسة نشر يقرها المالك. تعرض صفحة الإنتاج البيانات التي تحذف والاستثناءات ومددها المعتمدة وقناة التواصل، وتختبر expired/reused/wrong OTP و throttle والحساب المجهول والتأكيد والتراجع عن الطلب قبل التنفيذ. Production للحذف يبقى NO-GO حتى ذلك.

## الأسرار والتشغيل

فُحص ملف Firebase المرفق دون طباعة قيم العميل؛ لم يُحفظ Service Account في Git/APK. الملفات الخاصة المحلية تجاهلها Git وبصلاحية 600. OAuth cached token داخل العامل فقط و umask0077؛ logs تبقي أكواد الحالة ومعرّفات التشغيل اللازمة دون bearer أو payload أو SQL/bindings. متغيرات Production مستقلة، و Firebase UAT مرفوض هناك، والتوقيع والـ package والـ API الرسمي شروط بناء fail-closed.

لم تُنشأ حسابات قبول حية مكررة أو تُعاد جلسات قديمة. أدلة v5/preflight المؤرخة 26 أكتوبر تبقى أدلة تاريخية للمصدر المحدد، ولا يُعاد استعمال one-shot fixture command كأنه اختبار جديد. التنظيف بعد القبول يخص run IDs وحسابات/ملفات اصطناعية معروفة فقط بعد حفظ ما يحتاجه المالك؛ لا حذف شامل للـ bucket أوالجداول أو queue.
