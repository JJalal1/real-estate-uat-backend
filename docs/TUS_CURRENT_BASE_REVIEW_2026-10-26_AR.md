# مراجعة #11 على الأساس الموحد الحالي

هذه الدفعة امتداد لـ PR #115 وليست تطبيقًا بديلًا. قورنت النسخة الأصلية `3f89182521910bfd910a960bb5a4f2a55a919be3` بالأساس الموحد ثم بعمل PR #160 حتى `56c774f0056f4ad18da46bcd1c9a3c6bd5fb1d04`. أُبقيت حماية الصور والمراجعة والجلسات الحالية؛ حُل تعارض اختبار PostgreSQL بإضافة اختبار intent إلى المجموعة الحالية.

## ما تغير

- المستودع يثبت اعتماد الجلسة عند إنشائه، ويرفض الطلب والنتيجة المتأخرة بعد بدء تبديل الحساب.
- نطاق جلسة TUS المحلي يضم هوية المالك والمسودة ومفتاح الصورة وبصمة الملف؛ لا يضم bearer أو توقيع الرفع. يمكن للحساب نفسه استئناف الملف بعد تسجيل جديد، ولا يشترك حساب آخر في النطاق.
- النقل يرفض رؤوس Laravel وJWT ذي `service_role`، ويفحص الجلسة قبل الشبكة وبعدها وقبل إرسال الجزء التالي. يحفظ عنوان الجلسة دون query في ملف خاص داخل `no_backup` على Android وباستبدال ذري، ويمنع عمليتي رفع متزامنتين للنطاق نفسه.
- اختبارات إضافية لتبديل الحساب أثناء POST/HEAD/PATCH، وعدم تأكيد النجاح بعد التبديل، ومنع السباق وتسريب bearer، ورفض نتائج المسودات المتأخرة. نتائجها لا تُسجل ناجحة حتى تنتهي CI لهذا الرأس.

## بوابة التفعيل باقية

لم يدمج هذا الفرع في UAT، ولم تطبق هجرته، ولم تتغير أعلام الرفع. الجرد الحي وجد أن الجدول غير موجود، وأن bucket خاص لكن حد الحجم وأنواع MIME غير مضبوطين. ذلك مانع تفعيل يجب معالجته ضمن الموافقة، وليس تصريحًا بتوسيع GRANT أو RLS.

قبل الهجرة: نسخة PostgreSQL مشفرة كاملة ضمن الصلاحيات مع توثيق أي managed schema غير قابل للتصدير، ونسخة بايتات Storage أو حماية مكافئة قابلة للاستعادة، ومفاتيح الإعداد الضرورية منفصلة، واستعادة مستقلة متحققة، وفحص ملكية وصلاحيات، وخطة تراجع وموافقة المالك. PostgreSQL metadata أو مخطط فقط لا يفي بالبوابة. Supabase Pro ليس شرطًا تقنيًا لإجراء dump يدوي عبر اتصال آمن؛ النسخ المدفوعة لا تتضمن بايتات Storage تلقائيًا.

بعد الموافقة: طبّق الهجرة وحدها، تحقق من القيود وRLS ورفض الأدوار العامة، اضبط admission الآمن للـ bucket، فعّل canary لحساب اصطناعي واحد، اختبر 6MiB ثم انقطاع/HEAD/تجديد/offset خاطئ/حساب آخر/finalize ملتبس/مسح المسودة وتطهير intent بعد انتهاء توقيعه، ثم Android فعلي. لا تعمم العلم قبل نجاح ذلك. التراجع يغلق العلم أولًا ويحتفظ بجدول tombstones ومهمة التطهير إلى انتهاء كل توقيع؛ لا تنفذ down على جلسات نشطة.

المتبقي ليس اختبار Widget فقط: Android مع قتل التطبيق وإعادة فتحه والشبكة الضعيفة ومصدر ملف اختفى، وقياس bytes/زمن الرفع والتطهير في المورد الفعلي. دليل البروتوكول التاريخي لا يحل محل هذه البوابة ولا النسخة والاستعادة.
