# تحسين انتظار الرئيسية — 15 أكتوبر 2026

المستخدم جرّب APK 1039 وأرسل شاشة «الخادم غير متاح مؤقتًا» مع بطء شديد رغم قوة الإنترنت. يتناول هذا التغيير تحميل الرئيسية فقط ويحافظ على البحث والصوت والشروط والحدود المالية والصلاحيات.

## القياس قبل التعديل

نفّذ CI التشخيصي `38640113092` ست قراءات عامة دون تسجيل دخول أو تعديل بيانات: أول `/api/health` استغرق 39,999 مللي ثانية؛ أول `/api/marketplace` استغرق 6,708؛ تكراره 960؛ فلتر الشقق 476؛ المواقع 466؛ والصحة اللاحقة 518. كلها أعادت 200 مع بيانات سليمة. لم يتكرر 5xx المصوَّر. هذا يتفق مع بدء الخادم بعد الخمول، لكنه لا يثبت السبب الوحيد لكل خطأ أو زمن شبكة الهاتف. سجل النتائج مستقل عن أي حساب أو بيانات حساسة.

خادم UAT الحالي موثّق سابقًا على Render Free. توضح وثائق Render الرسمية أن خدمة Free تتوقف بعد 15 دقيقة خمول وقد يستغرق تشغيلها نحو دقيقة: https://render.com/docs/free#spinning-down-on-idle . لم يتم تغيير الخطة أو إنشاء مؤقت لإبقائها تعمل أو نشر خدمة جديدة. مساحة Render ليست مؤكدة لهذه المهمة؛ سؤال الاختيار لم يتلق إجابة، لذلك لم تُقرأ سجلات أو مقاييس الحساب الداخلية. القياس من واجهات التطبيق العامة عبر CI.

## التغيير

- إعادة محاولة محدودة للقراءتين العامتين `/marketplace` و`/marketplace/locations` في UAT فقط عند 502/503/504 أو مهلة/خطأ اتصال، بحد إجمالي 75 ثانية يشمل الانتظار. لا إعادة تلقائية لـ500 أو أخطاء الصلاحيات والتحقق، ولا لأي كتابة أو Gemini.
- إلغاء طلب الرئيسية وانتظار إعادة المحاولة عند التخلص من الصفحة/استبدال الفلتر؛ تجاهل الاستجابة القديمة.
- الاحتفاظ بالتحميل العام الناجح فقط 45 ثانية في ذاكرة مزود Riverpod، منفصلًا لكل منطقة ونوع. التحديث اليدوي ومراجعة بيانات العقارات يبطلانه. لا ذاكرة دائمة ولا تغيير لصلاحيات تفاصيل العقار.
- رسالة تحميل تتغير بعد ست ثوانٍ لتوضح استمرار المحاولة. الفشل في تحديث بيانات سبق تحميلها يبقي البطاقات مع تنبيه واضح؛ الفشل الأول يبقى قابلًا لإعادة المحاولة.

البحث الذكي والصوت وجلسة البحث مستقلون عن تحميل الأقسام. لم تتغير ملفات Android أو backend أو المكتبات أو الأصول أو حسابات UAT. بدء الخادم بعد الخمول لا يصبح فوريًا بهذه التغييرات؛ التحسن المقصود هو التعافي وتقليل الطلبات المتكررة والحفاظ على تفاعل الواجهة.
